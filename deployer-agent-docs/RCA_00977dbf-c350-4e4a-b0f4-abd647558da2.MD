# RCA — build_image failure (run 00977dbf-c350-4e4a-b0f4-abd647558da2)

## Symptom
`build_image` fails during the frontend build:
```
> vite build
sh: 1: vite: not found
error Command failed with exit code 127.
```

## Root cause — App architecture does NOT match the deployment template
The deployment is configured with template **`fastapi_react_mongo_shadcn_base_image`** (FARM: Python FastAPI backend + React frontend, Python base image). That template builds the frontend with `cd frontend && yarn install && yarn build` and runs a **Python** backend from `backend/` (expects `server.py` + `requirements.txt`).

The actual source in the preview pod is a **Node.js monorepo**, not a FARM app:
- `client/` — Vite + React frontend (`client/package.json` → `"build": "vite build"`, vite is a devDependency)
- `server/` — Express/Node backend, ESM (`server/src/index.js`, `import express ...`)
- `shared/` — shared JS modules
- root `package.json` (`name: du-nzo`) orchestrates both (`"build": "npm run build --prefix client"`)

The template's expected directories are empty stubs:
- `backend/` contains only `.env` + a generic default `requirements.txt` — **no `server.py`/`main.py` anywhere** (verified with `find`).
- `frontend/` contains only `.env` — **no package.json, no source**.

### Why the build throws `vite: not found`
The template runs `yarn install && yarn build` inside `frontend/`. Because `frontend/` has no `package.json`, yarn walks up and resolves the **root** `package.json`, whose `build` script is `npm run build --prefix client` → `vite build`. But the root-level `yarn install` never installed `client/`'s devDependencies (where `vite` lives), so `vite` is not on PATH → `sh: 1: vite: not found` → exit 127.

### Why a manifest fix is not appropriate
Even if the frontend build were patched, the app still cannot run on this template: the runtime is a **Python base image** with no Node runtime, and the backend is an **Express/Node** server with no FastAPI `server.py`. Making this work would require swapping base images and the entire backend build/runtime to Node — a full re-platform, not a manifest tweak. This is a source/structure problem, not a build-manifest, secret, tier, or infra problem.

## Recommended fix (E1 / main agent — source change required)
Pick ONE:
1. **Restructure to the FARM template** this deployment uses: a Python FastAPI app in `backend/` (`server.py` + real `requirements.txt`) and a React app in `frontend/` (its own `package.json` with a `build` script and all deps). Port the current Express routes (`server/src/index.js`) to FastAPI and move `client/` into `frontend/`.
2. **Or** deploy this app with a template that natively supports a Node client+server monorepo (Node runtime for `server/`, Vite build for `client/`), instead of the FastAPI/React template.

No deployer-side fix (manifest/secret/tier) can resolve this; the pipeline was not resumed.

- Build log: `#38 [frontend-build ...] yarn install` then `> vite build` / `sh: 1: vite: not found` / `exit code 127`.
- `backend/` = only `.env` + generic requirements.txt; no `server.py`/`main.py` (find returned nothing).
- `frontend/` = only `.env`; no package.json.

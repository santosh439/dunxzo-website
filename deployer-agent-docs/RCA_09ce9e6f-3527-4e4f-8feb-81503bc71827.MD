# RCA — Deploy run 09ce9e6f-3527-4e4f-8feb-81503bc71827

## Summary
Initial deploy failed at the **pull_source** step. The step could not read `backend/.env` from the preview pod while preparing the build context, so no source archive was ever produced and the pipeline halted before build.

## Symptom / Evidence
Failed step (`get_step_status`) — build/pull_source:
```
prepare build context: read envs: read env file backend/.env:
open /tmp/agent-env-.../app/backend/.env: no such file or directory
(type: PathError)
```
- Both recent runs failed **identically**:
  - 09ce9e6f-3527-4e4f-8feb-81503bc71827 → `.../app/backend/.env: no such file or directory`
  - 0d85a463-196d-42bd-bf06-2861dc25675b → same error
- The failure is deterministic (same cause on back-to-back runs), not a transient preview/infra blip.
- No eph sandbox could be spawned to inspect the source — `eph_source_access_failed` on every attempt — because pull_source failed before uploading any source zip. This confirms the failure is at the very start of context prep, consistent with the missing file.

## Root cause
During `pull_source`, the pipeline copies the app source from the preview pod's `/app` and reads `backend/.env` to cache the pod's env vars (used as a fallback tier for the later write_secrets step). The file `/app/backend/.env` does **not exist** in the preview pod, so the env-read raises a PathError and the step aborts.

This is a **source/preview-environment** problem — the FastAPI+React+Mongo template expects `backend/.env` to be present. It is missing (deleted, never created, or excluded from the checkout).

## Why not a manifest/infra fix
- `pull_source` runs before build_image; none of the 6 deployment manifest files control which env files pull_source reads, so this is not manifest-fixable.
- Not OOM/tier, not secrets-tab (that governs production secrets, not the preview `backend/.env` the pull step reads), not DNS/domain.
- Retrying `resume_pipeline` with no change would reproduce the same PathError (both prior runs already did).

## Fix
E1 / main agent must restore `backend/.env` in the preview pod at `/app/backend/.env` (standard FARM template file, typically containing `MONGO_URL` and `DB_NAME`). Once the file exists in the preview checkout, re-trigger the deploy.

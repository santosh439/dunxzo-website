# RCA — Custom domain Error 1001 (du-nzo.com / www.du-nzo.com)

## Problem statement
User reports Cloudflare **Error 1001 (DNS resolution error)**, Ray ID a441c5af193150fb, when visiting `www.du-nzo.com` / `du-nzo.com`. App itself is expected to be live.

## Investigation & evidence
- `describe_deployment_state`: deployment `dunxzo-preview`, active run `76e23450-5af3-4619-a6f1-0efd0914879a`, status success, frontend_type **cloudflare**. Both domains present and `verified: true`.
- `list_domains`:
  - `du-nzo.com` → verified: true, **ssl_status: active**, provider: cloudflare, validation: http, cf_custom_hostname_id: ff667f2e-d416-4bf1-8d0b-ce9c09109479
  - `www.du-nzo.com` → verified: true, **ssl_status: active**, provider: cloudflare, validation: http, cf_custom_hostname_id: 3615faa8-c9fa-4625-abe9-d21ff4c34098
- `check_domain_status`: both domains **linked: true** (DNS A-record check passes from our side).
- `preview_health_check` on default URL `https://dunxzo-preview.emergent.host/`: **HTTP 200**, 645 ms, real DU-NZO app content. App is healthy.

## Root cause
Everything on the Emergent / Cloudflare-for-SaaS side is correct: both custom hostnames are verified and their SSL certificates are **active**. The failure is in the **user's DNS configuration at BigRock**.

The user created **A records** pointing the apex at generic Cloudflare anycast IPs:
- `@` → 162.159.142.117, 172.66.2.113
- `www` → CNAME to du-nzo.com

For a Cloudflare-for-SaaS custom hostname, the domain must resolve (via **CNAME**) to the platform's **target/fallback hostname** (`dunxzo-preview.emergent.host`). Pointing A records at arbitrary Cloudflare edge IPs sends requests to Cloudflare edge nodes that have no route configured for this custom hostname, which Cloudflare returns as **Error 1001 (DNS resolution error)**. The presence of the Ray ID confirms the request reached Cloudflare but could not be resolved to the correct origin/hostname.

## Suggested fix (USER — DNS at BigRock)
1. Remove the hard-coded A records (162.159.142.117, 172.66.2.113) on `@`.
2. Point the domain at the platform target hostname:
   - `www` → **CNAME** → `dunxzo-preview.emergent.host`
   - Apex `@` (du-nzo.com): CNAME is not allowed on an apex at most registrars. Use BigRock's **CNAME flattening / ALIAS / ANAME** record (if supported) → `dunxzo-preview.emergent.host`. If BigRock does not support ALIAS/flattening, redirect the apex to `www` (or host DNS on a provider that supports flattening).
3. Allow DNS propagation (up to a few hours) and re-test in an incognito window.

## Verification notes
- Verified on platform side only (verification status, SSL active, DNS linked check, default-URL health). The user-side DNS change cannot be applied or verified from here — it is owned by the user at their registrar.
